= The game of Chess - Team Rooks

This repository contains a student project created for an ongoing lecture on object-oriented programming with Kotlin at HWR Berlin (summer term 2026).

WARNING: This code is for educational purposes only.
Do not rely on it!

== Feature-Liste

* [x] Schachbrett, Figuren und Startaufstellung
* [x] Legale Züge und Schlagen von Figuren
* [x] Spielerzuordnung, Zugwechsel und Spielstatus
* [x] Rochade, en passant und Bauernumwandlung
* [x] Schach, Schachmatt, Patt und mehrere Remis-Regeln
* [x] Zughistorie für Rücknahme und 50-Züge-Regel
* [x] Dateisystem-Persistenz als JSON
* [x] Optionale PostgreSQL-Persistenz
* [x] Anbindung an CLI und REST-Service

== Modulstruktur

[source]
----
.
├── core/                        # Domänenlogik (keine Abhängigkeiten nach außen)
├── persistence/
│   ├── persistence-filesystem/  # Persistenzadapter: Dateisystem
│   └── persistence-sql/         # Persistenzadapter: PostgreSQL (via Exposed + Liquibase)
└── applications/
    ├── config/                  # Konfigurationsmodell (AppConfig, ConfigLoader)
    ├── service/                 # Spring Boot REST-Service
    └── cli/                     # Kommandozeilenanwendung (Clikt)
----

== Schnellstart

=== Projekt bauen und testen

[source,bash]
----
just test
----

Führt alle Tests aus.
Docker ist *nicht* erforderlich – SQL-Tests werden nur ausgeführt, wenn `RUN_DOCKER_TESTS=true` gesetzt ist (siehe <<sql-tests>>).

=== CLI

Nach einem Build kann die CLI über `just cli` genutzt werden:

[source,bash]
----
just build

just cli startGame --game-id demo-game --white-player-id alice --black-player-id bob
just cli onGameID demo-game getGame
just cli onGameID demo-game makeMove --player-id alice --from E2 --to E4
----

Bei einer Bauernumwandlung kann die gewünschte Figur angegeben werden:

[source,bash]
----
just cli onGameID demo-game makeMove --player-id alice --from E7 --to E8 --promotion-piece QUEEN
----

=== Persistenz konfigurieren

Die aktive Persistenz steht in `applications/config.json`.
Standardmäßig ist `FILE_SYSTEM` gesetzt; für PostgreSQL kann der Wert auf `SQL` geändert werden.
Dafür muss die Datenbank laufen (siehe <<docker-und-postgresql>>).

=== Alle verfügbaren Befehle anzeigen

[source,bash]
----
just
----

.Übersicht der wichtigsten Befehle
[cols="1,3"]
|===
| Befehl | Beschreibung

| `just test` | Alle Tests ausführen
| `just build` | Projekt bauen und ins lokale Maven-Repository installieren
| `just compile` | Nur kompilieren (ohne Tests)
| `just service` | Spring Boot Service starten (erfordert vorheriges `just build`)
| `just cli [args]` | CLI ausführen (erfordert vorheriges `just build`)
| `just start-db` | PostgreSQL-Datenbank starten (erfordert Docker)
| `just stop-db` | PostgreSQL-Datenbank stoppen
| `just discard-db` | PostgreSQL-Datenbank stoppen und alle Daten löschen
| `just mutation-test` | Mutationstests für das `core`-Modul ausführen (PITest)
| `just mutation-test-open` | Aktuellen PITest-Bericht im Browser öffnen
|===

== Tests

Die Tests laufen mit:

[source,bash]
----
just test
----

Das entspricht `./mvnw verify`.
Docker-basierte SQL-Tests sind dabei deaktiviert, solange `RUN_DOCKER_TESTS` nicht gesetzt ist.

Mutationstests werden nur für das `core`-Modul ausgeführt:

[source,bash]
----
just mutation-test
----

Der Bericht liegt danach unter `core/target/pit-reports/index.html` und kann mit `just mutation-test-open` geöffnet werden.

[#docker-und-postgresql]
== Docker und PostgreSQL

=== Docker installieren

Docker Desktop kann unter https://www.docker.com/products/docker-desktop/ heruntergeladen und installiert werden.
Nach der Installation muss Docker Desktop gestartet sein, bevor die folgenden Befehle ausgeführt werden können.

=== PostgreSQL-Datenbank starten

Eine lokale PostgreSQL-Datenbank ist über Docker Compose vorkonfiguriert:

[source,bash]
----
just start-db
----

Die Datenbank ist anschließend unter `localhost:5432` erreichbar (Verbindungsdaten siehe `applications/config.json`).

=== PostgreSQL-Datenbank stoppen

[source,bash]
----
just stop-db
----

Um die Datenbank mit einem *frischen Zustand* (alle Daten gelöscht) neu zu starten:

[source,bash]
----
just discard-db
just start-db
----

[#sql-tests]
== SQL-Tests aktivieren

Die Tests, die Docker und PostgreSQL benötigen (`SqlPersistenceTest`, `ServiceSqlTest`, `CliSqlTest`), sind mit `@EnabledIfEnvironmentVariable(named = "RUN_DOCKER_TESTS", matches = "true")` geschützt.
Damit läuft `just test` ohne Docker und ohne lokale PostgreSQL-Instanz.

Um die SQL-Tests bewusst mit Testcontainers auszuführen, muss Docker Desktop laufen und die Umgebungsvariable gesetzt werden:

[source,powershell]
----
$env:RUN_DOCKER_TESTS = "true"
./mvnw.cmd verify
----

Auf Linux/macOS:

[source,bash]
----
RUN_DOCKER_TESTS=true ./mvnw verify
----

Die normale Anwendung verwendet die Persistenz aus `applications/config.json`. Standardmäßig ist dort `FILE_SYSTEM` gesetzt; `SQL` wird also nur verwendet, wenn die Konfiguration entsprechend geändert und eine PostgreSQL-Datenbank gestartet wurde.
